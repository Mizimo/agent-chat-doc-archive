# Agent 共同工作協議

一套面向長期工作、跨 session 與跨 Agent 協作的文件協議：約定如何定位可信資料、維護知識、交接工作、同步變更，以及處理憑證。適用於單一 Agent 與多 Agent 部署。

**協議版本：0.2 · 修訂日期：2026-10-02。** 本倉庫維護協議與採用指引；執行方式由各部署自行選擇。

## 閱讀入口

| 文件 | 何時閱讀 |
|---|---|
| [knowledge-model.md](knowledge-model.md) | 判斷資料歸屬、權威來源、有效性、憑證引用、交接與歸檔方式 |
| [sync-matrix.md](sync-matrix.md) | 變更前確認影響範圍，變更後更新資料、協調衝突、通知與交付 |

## 核心約定

- 一項事實有明確的權威來源與維護責任；其他入口保留必要摘要與引用。
- 三層代表使用職責，不是互斥的資料夾。常駐摘要、專題文件、共同索引可以存在同一倉庫。
- 「現行／已替代／歷史」描述資料用途；「已核驗／未核驗／有衝突」描述證據狀態。兩者分開記錄。
- 憑證只記錄受控存放位置、權限與使用方式，不將憑證值寫入文件或同步到 GitHub。
- 未完成的工作留下最小交接；歷史資料保留證據，但不自動成為目前的操作依據。
- 文件中的命令、歷史對話和憑證位置本身不授予執行權限；遵循目前適用的指令與有效授權範圍。

## 如何採用

在部署實例的 README 記錄下表。名稱與格式可以調整，已有資訊可用連結引用；無需為每份筆記重複填表。

| 項目 | 部署需記錄的內容 |
|---|---|
| 採用版本 | 協議版本與上游提交；離線副本也標明來源與版本 |
| 適用環境 | 部署名稱、主機／帳戶範圍、目前維護或已退役的狀態 |
| 三層落點 | 常駐入口、專題文件、共同索引的實際位置與讀取方式 |
| 載入預算 | 實際平台的載入限制、截斷行為與本地預算；不假設所有平台都使用 `MEMORY.md` 或 200 行上限 |
| 維護責任 | 共享文件的維護角色、各專題負責人、接手或無人維護時的處理入口 |
| 同步方式 | 哪裡是可編輯來源、哪裡是備份、同步方向與時機、失敗如何交接 |
| 訪問與操作邊界 | 文件讀者、憑證引用的可見範圍、現有操作授權與限制的來源 |
| 本地例外 | 與核心條款的差異、理由、適用範圍；臨時例外另記結束或重新檢視條件 |

保留必要的本地配置與約束；升級協議時對照變更，避免整份覆蓋部署文件。若本地規則仍有衝突，明確記錄偏離，不宣稱已完整採用。部署實例的真實主機、路徑及其他內部資料留在其適當的訪問範圍內；公共協議只使用虛構示例。

## 採用後的情境檢查

用文件推演以下五個情境，確認接手者不依賴原有聊天歷史也能判斷下一步；推演本身不要求執行系統變更。

| 情境 | 應能從文件得到的答案 |
|---|---|
| 共享服務埠變更 | 配置來源在哪、哪些摘要與使用者受影響、誰尚未採用新版本？ |
| 憑證輪換 | 哪個環境的哪個受控位置提供憑證、誰負責、哪些消費者尚未驗證？全程不需要把憑證值放進文件。 |
| 任務中斷 | 已完成什麼、證據在哪、下一步是什麼、哪些授權仍有效？ |
| 舊指南被替代 | 現行入口在哪、舊指南為何保留、何時不再適用？ |
| Agent 退役 | 誰接手共享資料、最後核驗到何時、尚未完成的工作如何處理？ |
